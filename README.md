# 校园网助手 v0.3.2

个人使用的 Windows/macOS 托盘应用，共用 Python＋PySide6 核心。已根据两个入口分别只读检查 Dr.COM 页面、静态脚本和配置：公共网 `192.168.255.4`，宿舍网 `172.19.0.1`。

## 当前验证状态

### v0.3.1 表单与认证状态联动

- 识别结果通过 Qt 跨线程信号即时更新界面：切换宿舍／公共配置表单，入口、独立凭据、服务商随场景切换；共用账号密码不被切换覆盖。
- 独立显示只读的“当前认证入口”，与尚未保存的配置编辑字段分开。不要直接修改公共配置为宿舍地址。
- 手动切换编辑场景会暂时取消“表单自动跟随”，方便编辑另一个场景但不改变实际认证目标；重新勾选可恢复跟随。
- 显示缺少服务商、缺少凭据等本机配置问题为“需要检查配置”，而不是“认证被拒绝”。明确账号错误、欠费、停用才显示认证被拒绝。相同场景配置阻断继续保留原始配置提示；切到不同场景不会继承原场景的阻断。
- 保存服务商后立即重建配置并检查，认证使用保存的宿舍入口、服务商后缀及共用凭据，不向公共入口提交宿舍凭据。
- 修复了表单加载时服务商信号误触发，以及场景切换可能将占位选项当作后缀的问题；尚未保存的编辑在切换时保留于对应场景草稿。
- 新增实际 Qt 后台线程集成测试，完整覆盖识别宿舍、显示配置缺失、自动切换表单、选择服务商、保存重载、模拟认证成功。所有认证请求都通过离线假响应测试，没有为了验证注销现有连接。


### v0.3.0自动识别重构

- 自动模式在每次网络变化或首次场景检查时严格按“公共网 → 宿舍网”顺序探测。公共网页面不是已支持门户时才访问宿舍入口；第一个成功识别的入口立即确定场景，不再因为两个入口都可达而停住。
- 公共和宿舍都无法识别时，顶部明确显示“当前不在可识别的校园网环境（公共网和宿舍网均未识别）”，不会提交账号密码。
- 即使公网探测已通过，也会只读识别当前校园场景；因此不能再仅凭公共HTTPS探测把程序当成公共网。联网状态和场景状态分开显示。
- 从旧版本迁移的配置会把旧的默认公共场景迁移为自动识别；v0.3.0中用户明确保存的公共网／宿舍网选择仍是手动覆盖。

- 用户提供的 macOS 公共网截图显示“认证成功且互联网已连通”，对应提交认证、门户成功响应和公网探测通过的完整分支。
- 宿舍配置与页面已现场只读验证，已增加宿舍适配、四个服务商选项和模拟认证测试。宿舍真实未认证场景的提交还未验证，不主动注销现有会话。
- 用户已将此前版本构建并运行在 Windows 实验室机器，但该机器的午夜恢复尚未现场验证。Windows目前保持原先交付版本；本轮Mac优化尚未同步Windows源码包，待Mac确认后再更新。
- 模拟时钟已测试跨午夜停网、00:06 提前恢复、00:10 恢复和00:12 延后恢复；不以模拟测试替代整夜现场验证。

## 场景与服务商

1. “认证场景”选择“自动识别”，点击“保存配置”，以后才能自动在两个场景之间切换。手动选择公共网或宿舍网是覆盖自动识别，不会被程序擅自改回。
2. 已联网时也只读识别场景，界面显示“当前识别场景”。网络变化后重新识别；同一网络正常联网的周期检查不重复扫描入口。
3. 自动模式严格先访问公共入口，识别失败再访问宿舍入口。第一个有效门户确定场景，识别过程只读访问，不向两个入口试密码。两个入口都无法识别时显示未识别到校园网；不可达也可能是临时网络故障，不是确定不在校园网的证据。
4. 表单默认跟随检测结果自动切换；识别宿舍后，配置入口切换为宿舍配置，显示“校园网／中国移动／中国联通／中国电信”下拉框，并恢复已有保存的服务商。首次选择后点击保存。服务商是账号归属，不能仅凭所连网络推断；首次需要用户明确选择，之后自动复用。旧配置中空后缀不会被当作已确认选择。
5. 场景先只读查在线状态；已在线时不提交凭据。只有明确未在线、所需配置和参数通过验证时才提交一次认证。
6. 两入口已确认配置不同：公共账号有 PC 前缀 `,0,`，宿舍不加该前缀；宿舍服务商后缀按现场页面分别是空、`@cmcc`、`@unicom`、`@telecom`。未知配置变化会阻止认证，不猜测密码变换或登录方式。

## 后台和午夜逻辑（北京时间）

- 界面定时器每5秒检查调度是否到期；联网每60秒探测，断网每30秒检查或重试。
- 00:00–00:10 每60秒检查／重试；00:00、00:12 所在分钟额外触发一次。受系统调度影响，不保证精确到00秒。
- 时间窗口不禁止提前恢复：只要服务实际恢复即可认证。00:10之后仍失败会继续重试，不是尝试一次就停止。
- 临时故障继续重试；未知失败连续三次后退避为300秒。明确账号、欠费、停用、配置错误暂停提交，修改配置或点击“重试”才恢复。
- 唤醒、网卡地址变化、网络可达状态变化触发检查；检查合并执行，切网／暂停会取消旧请求。
- 需要机器开机、保持唤醒、程序运行、自动检查启用且未暂停。不能在电脑关机／睡眠期间执行，也不能恢复物理断开的Wi-Fi或网线。
- 关闭窗口留在托盘；“退出”停止程序。开机启动默认关闭，启用后保存配置。开机启动不是从睡眠中唤醒机器。

## 网络、安全和日志

公网探测使用两个HTTPS地址，验证预期响应。探测成功不单独说明校园账号本轮认证成功，界面会明确区分。公网请求总时限4秒，门户请求10秒，使用可终止的轻量独立请求进程覆盖DNS/TLS/读取等阻塞；不修改系统代理、VPN或网卡。门户与公共探测仅绕过系统HTTP代理，网络仍可能受VPN路由影响。

认证按现场提供的HTTP GET接口构造请求；它不是加密凭据传输。密码明文保存在用户目录 `校园网助手/config.json`。日志和诊断不输出账号、密码、令牌、认证URL或服务端原始响应。

从v0.2.0起在同一配置文件夹记录 `events.jsonl`，包含北京时间、版本、触发原因、场景、结果状态、是否尝试提交认证和下次间隔。午夜原因标为 `midnight` 或 `midnight_extra`。文件超过约1MB轮转到 `events.previous.jsonl`。可在次日检查是否实际运行、重试和恢复，不依赖口头保证。保存后生效；外部编辑配置后点击“重载文件”。

## 构建

需要Python 3.10或更新版本。使用者拿到已打包应用后无需Python；构建者需要Python及可用依赖源。

macOS：

```sh
./build.sh
```

输出 `dist/校园网助手.app`。更新时先退出旧进程再打开新应用，不能仅关闭窗口。

Windows在项目文件夹的PowerShell执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

脚本是纯ASCII，默认显式使用官方PyPI；可以用 `-IndexUrl` 指定自己的可信HTTPS源。不关闭TLS验证。受管理机器需遵循管理员策略。

输出 `dist\校园网助手\校园网助手.exe`。复制整个文件夹，不要仅复制exe。请先在旧程序点“退出”，再替换运行目录并启动新版。当前Mac窗口标题为v0.3.2，Windows交付包仍保持此前版本。不能在macOS直接生成Windows构建。

离线测试：

```sh
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
```

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\.venv\Scripts\python.exe -m pytest -q
```

只读打包诊断（不读取用户凭据，不调用登录／注销）：

```text
校园网助手 --diagnose-network 输出JSON路径
校园网助手 --diagnose-portal 输出JSON路径 --profile=dorm
校园网助手 --diagnose-portal 输出JSON路径 --profile=auto
```

验证码、短信、跨学校适配不在支持范围。Windows新版本的打包、托盘、子进程、开机启动和实际夜间运行仍需在Windows机器验证。

## v0.3.2 资源优化与仓库准备

- `main.py`只负责轻量入口分发；桌面界面在`campus_assistant/gui.py`，仅正常打开应用时加载Qt。
- 网络请求以短生命周期的独立标准库进程运行，不再保留multiprocessing的resource_tracker辅助进程。仍保持总超时、取消、代理绕过、TLS校验、同主机跳转和响应大小限制；密码经私有stdin传递，不在命令行或日志中出现。
- 窗口隐藏后停止倒计时、等待秒数和动画等纯显示计时器；网络心跳、切网检查和午夜调度继续运行。重新显示时读取真实期限，不需要后台逐秒递减一个显示计数。
- 内存/CPU采用原生Mac打包应用测量，不用源码offscreen结果代替；测试仅访问隔离的本机回环服务器，不加载个人账号或登录真实门户。方法和实测结果见`docs/RESOURCE_USAGE.md`。
- 性能测试可复现：`tools/profile_resources.py`。原始采样放在`.cache/resource-profiles/`，默认不提交Git。
- 尚未为这轮改动重建或更新Windows源码包/可执行文件；Mac结果不代表Windows结果。
- 本机配置、日志、虚拟环境、缓存、构建目录和系统元数据已加入`.gitignore`。上传GitHub前仍应检查暂存文件，不要提交真实凭据或个人数据；当前工具没有建立远程仓库或推送。

当前回归验证：123项测试及2项子测试通过。资源优化Mac构建已通过本地代码签名完整性检查；Windows尚未为资源优化版本构建和测试。
