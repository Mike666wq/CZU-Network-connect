# Mac 资源占用报告：v0.3.2

测量日期：2026-10-05。环境为 Apple M1、8 GiB 内存、macOS 26.6.2 arm64。运行 **原生 PyInstaller 打包应用**，不是只测 Python 脚本，也不是只测 offscreen 界面。

## 指标与方法

- 外部观察器每约0.2秒采样，统计主进程及其所有子进程；观察器本身不计入应用数据。
- RSS是驻留内存合计，可能重复计入共享页。不要把进程树RSS直接称作活动监视器的应用内存，或与footprint混为同一指标。
- 系统 `footprint` 工具提供物理内存footprint快照，正文明确标注其为单次系统快照，而非连续全场景峰值。
- MiB为1024²字节。CPU由相邻进程CPU时间增量计算，100%代表占满一个核心；新建短命进程的首次采样CPU可能未全部计入，因此CPU数字是近似观测值。
- 测试实例不读个人config.json，账号密码为空；HTTP只访问自建127.0.0.1服务，模拟204响应和1.25秒响应等待，使用真实生产请求传输路径。没有访问校园门户、提交登录、注销或修改网络。
- 公平对比阶段相同：启动、可见空闲、隐藏空闲、显示窗口并周期检查、检查后隐藏。优化版另延长30次连续请求，以观察内存和进程释放情况。公共对比阶段的CPU和内存均从各自独立原生应用实例采集。

## 结果

| 指标 | 原版 | 优化版 |
|---|---:|---:|
| 后台空闲footprint快照（进程树） | 95.255 MiB | **74.284 MiB** |
| 后台空闲RSS中位数（进程树） | 217.95 MiB | **169.42 MiB** |
| 请求活跃阶段观测RSS峰值（进程树） | 273.64 MiB | **223.95 MiB** |
| 后台空闲平均CPU | 0.295% | **0.228%** |
| 可见空闲平均CPU | 0.489% | 0.477% |
| 活跃检查阶段平均CPU | 8.938% | 6.587% |
| 后台空闲进程数 | 2 | **1** |
| 活跃阶段最多进程数 | 3 | **2** |

后台footprint降低约22.0%，RSS中位数降低约22.3%。活跃检查时有进程启动和UI绘制的瞬时CPU突发；优化版某些采样峰值约90%（单核心口径），不能声称CPU始终维持0.23%。

footprint活跃快照原版106.037 MiB、优化版99.114 MiB；这两次快照所处请求启动阶段不同，不能将它们当作所有请求的峰值或稳态内存。优化后的连续检查阶段另一次快照为84.160 MiB。

### 连续检查观察

优化版总测试约106.47秒，完成36次回环请求，其中末段30次为连续检查延长测试。主进程后台空闲RSS中位数约169.422 MiB，结束时约169.703 MiB，差约0.281 MiB；没有观察到明显单调增长。最后请求结束，没有遗留HTTP请求子进程。

这不是一整夜的泄漏测试，也不证明永久零增长。Qt/Python缓存、界面使用方式、响应体大小、TLS、其他机器和Windows都可能改变占用。

## 优化内容

1. **去除常驻multiprocessing辅助进程。** 原版resource_tracker后台占约20.4 MiB footprint、47.1 MiB RSS；新版请求完成后没有该常驻进程。
2. **轻量入口。** `main.py`先区分HTTP工作进程、诊断和GUI，HTTP子进程只加载标准库网络模块，不导入Qt或建立窗口。
3. **私有IPC与边界保留。** 凭据经stdin传递，不进入argv或日志。保留总超时、取消、进程终止回收、TLS验证、代理绕过、同主机跳转校验和1MB响应体上限。
4. **停止隐藏窗口的纯UI计时器。** 隐藏后停止倒计时和等待秒数刷新，动画也停止；网络心跳和午夜调度仍运行。显示窗口时重新读取实际调度期限，不依赖后台逐秒绘制。
5. **保留既有日志上限。** 界面历史最多160条，文件日志轮转，避免随运行时间无限增加展示对象。

未通过删除必要功能、降低安全校验或只测一个进程来制造低占用数字。保留Python和PySide6界面的前提下，不能把这个版本宣传为几MiB级应用或“数学意义上的绝对最小内存”。

## 复现

在macOS构建源码后，使用两个不同输出文件夹分别测量待比较版本：

```sh
./build.sh
.venv/bin/python tools/profile_resources.py \
  --executable 'dist/校园网助手.app/Contents/MacOS/校园网助手' \
  --output .cache/resource-profiles/my-run \
  --soak-cycles 30
```

需要允许启动原生GUI、读取本机进程统计和监听回环地址；无需访问互联网。不要用已经存在的输出文件夹覆盖先前测量。

公开的聚合数据见 `resource-metrics.json` 和 `resource-metrics.csv`。原始带PID和本机路径的数据仅在 `.cache/resource-profiles/`，已被Git忽略。Windows尚未为本轮改动构建或测量，不能用Mac数据代替Windows结论。

## 回归验证

最终123项测试及2项子测试通过。覆盖请求总超时、取消后进程回收、大响应体IPC、凭据不进入argv、轻量入口不加载Qt，以及原有识别、服务商、午夜调度和界面行为。优化版Mac应用已重新打包并通过本地代码签名完整性检查。


## v0.3.7：Scheduler 2.0 与 Qt 裁剪补充测量

测量环境仍为同一台 Apple M1 / 8 GiB / macOS 26.6.2 arm64。此轮使用已经通过代码签名验证的原生打包应用，并保留独立 campus-http-worker；网络流量仍只访问 127.0.0.1 回环测试服务，不读取个人配置，不提交校园认证。

### 调度与后台行为

- 稳定联网 heartbeat 从 60 秒改为 600 秒。
- 普通断网使用 30 / 60 / 120 / 300 秒退避。
- 23:58–00:08 使用 60 秒恢复节奏，00:08–00:15 使用 30 秒节奏。
- 原先每 5 秒调度轮询改为 single-shot deadline timer；系统网络变化事件可立即触发，60 秒接口签名轮询仅作为漏报兜底。

### 打包裁剪

PyInstaller 默认 Qt 插件会间接带入 QML、Quick、Pdf、VirtualKeyboard、Svg、OpenGL 等当前 Widgets UI 不使用的功能链。构建流程现在在最终签名前显式移除这些插件和依赖框架，同时保留 QtCore、QtGui、QtWidgets、QtNetwork、Cocoa platform plugin、Apple network-information plugin，以及独立 HTTP helper。裁剪后必须重新 codesign，并通过 frozen packaged smoke test。

| 指标 | v0.3.2 优化版 | v0.3.7 本轮长测 | 说明 |
|---|---:|---:|---|
| Mac .app 展开体积 | 约 118 MiB（本轮重建基线） | **约 94 MiB** | **约 -20.3%** |
| Mac ZIP | 约 44 MiB（本轮重建基线） | **约 34 MiB** | **约 -22.7%** |
| 后台空闲 RSS 中位数 | 169.42 MiB | **149.14 MiB** | 本轮约低 12%，但 RSS 受系统缓存影响 |
| 活跃检查 RSS 峰值 | 223.95 MiB | **210.86 MiB** | 本轮约低 5.8% |
| 连续 30 次检查 RSS 中位数 / 峰值 | — | **162.30 / 162.84 MiB** | 结束时无遗留 HTTP 子进程 |
| 后台空闲 footprint 快照 | 74.284 MiB | **104.613 MiB** | 未复现旧版较低快照，不宣称 footprint 改善 |
| 后台空闲平均 CPU | 0.228% | **1.725%** | 14 秒采样窗口噪声较大，不用于证明稳态 CPU 变差或变好 |

长测运行约 104.47 秒，共完成 36 次回环请求，其中末段 30 次为连续检查；auth_requests=0，结束时没有遗留 HTTP 子进程。Qt 裁剪的确定收益是发布体积；运行时内存数据有改善迹象，但 footprint 与短窗口 CPU 在不同运行间波动明显，因此不把它们宣传为稳定百分比收益。Scheduler 2.0 的主要运行时收益来自减少真实日常场景中的唤醒和公网请求次数，而这个 profiler 会主动触发检查，不适合用来量化“10 分钟心跳”带来的长期 CPU 节省。

最终验收：153 项测试和 2 项子测试通过；正式裁剪后的 macOS frozen smoke test通过，确认使用 campus-http-worker 完成回环请求；codesign --verify --deep --strict 通过。正式构建包未包含被裁剪的 10 组 Qt framework 链。


## v0.3.8：UI / UX 重构验收

本轮不改变校园认证协议与请求参数，重点重构展示语义和交互层：引入独立 Presentation Model，以结构化 State / reason 驱动标题、严重程度、流程节点、状态 Chip 和上下文操作；主界面改为“状态 / 设置 / 记录”三页结构，技术 Portal 参数默认收进高级设置。

状态页保留五步业务流程，但减少重复信息；认证失败与一般待配置明确区分为红色失败 / amber 待处理。午夜恢复窗口会直接显示当前 60 秒或 30 秒节奏。设置页增加密码显隐、未保存状态、异常字段定向高亮和精确跳转；后台检查不会主动抢占用户当前页面。

跨平台窗口与字体策略：macOS 默认 940×720、最小 820×700；Windows 默认 960×740、最小 840×700。macOS 使用 Apple System Font / PingFang SC，Windows 使用 Microsoft YaHei UI / Segoe UI；三页分别支持 Command+1/2/3 与 Ctrl+1/2/3 快捷键。

最终验收：**168 项测试和 2 项子测试通过**；macOS 原生 App 重新构建、codesign 校验与 frozen packaged smoke test 均通过。裁剪后 .app 展开体积仍约 **94 MiB**，未重新引入 QML / Quick / Pdf / VirtualKeyboard / Svg / OpenGL 功能链。本轮没有重新测量 Windows 运行时资源，因此不以 Mac 数据推断 Windows 内存或 CPU 表现。
